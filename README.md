## Лабораторная 03: конвейер обработки данных

Задача состоит в создании переиспользуемых этапов: генерации, фильтрации, преобразования и агрегации. `generate_numbers()` выдаёт числа из `range` по одному. `filter_by_condition()` оставляет значения по предикату, `filter_by_type()` отбирает заданный тип, а `transform_data()` применяет функцию к каждому элементу. Это генераторы: данные обрабатываются только при запросе следующего значения, без создания промежуточного списка.

`create_pipeline(*steps)` собирает этапы в одну функцию. Результат каждого этапа передаётся следующему; завершающий этап может вернуть число вместо итератора. `aggregate(data, func)` вызывает выбранную функцию агрегации. `sum_values()` и `average()` используют `functools.reduce`; среднее за один проход хранит только сумму и счётчик. Для пустого потока `average()` выбрасывает `ValueError`, так как среднее не определено.

Вспомогательные этапы показывают требуемые инструменты `itertools`:

| Функция | Инструмент | Поведение |
| --- | --- | --- |
| `batch_process()` | `batched` | Выдаёт списки не больше заданного размера; последняя партия может быть короче. |
| `take()` | `islice` | Выдаёт первые `count` элементов потока. |
| `concatenate()` | `chain` | Последовательно объединяет несколько потоков. |
| `group_sorted()` | `groupby` | Группирует соседние элементы с равным ключом. |
| `pairs()` | `combinations` | Строит пары разных позиций без учёта порядка. |
| `cartesian()` | `product` | Строит декартово произведение двух наборов. |

Для одной общей группы на каждый ключ вход `group_sorted()` должен быть заранее отсортирован по этому же ключу. Партия и группа материализуются по одной. `product` может хранить входные последовательности в памяти; это особенность `itertools.product`.

В `even_squares_pipeline()` функция `functools.partial` закрепляет параметры фильтрации и преобразования при сборке конвейера, а `functools.lru_cache` кэширует вычисление `square()`. Это готовая композиция этапов задания. Обычная последовательная обработка `n` элементов занимает **O(n)** времени без учёта стоимости пользовательских функций и **O(1)** дополнительной памяти до формирования партии или группы. Для партии/группы нужно **O(k)** памяти, где `k` — её размер.

## Лабораторная 04: файловый менеджер

`ValidatedFilename` и `ValidatedMode` реализованы как дескрипторы. `__set_name__()` запоминает имя приватного поля, `__get__()` читает его, а `__set__()` проверяет значение перед записью. Имя файла должно быть непустым и не содержать недопустимых символов. Допустимые текстовые режимы доступа: `r`, `w`, `a`, `r+`, `w+`, `a+`.

`FileManager` реализует контекстный менеджер. `__enter__()` открывает UTF-8 файл и возвращает менеджер. Методы `read()` и `write()` работают только пока файл открыт. `__exit__()` закрывает файл даже при исключении внутри `with` и возвращает `False`: исходная ошибка передаётся вызывающему коду. Ошибки открытия файла, например отсутствие файла при `r`, сохраняют обычное поведение Python.

`LogManager` сообщает об операциях через стандартный вывод. `SecureManager.check_permissions()` предварительно проверяет права чтения или записи с помощью `os.access()`. Эта проверка предварительная: права могут измениться до самого открытия, поэтому окончательное решение всё равно принимает файловая система.

`FileManagerWithLogging(LogManager, SecureManager, FileManager)` объединяет миксины и базовый менеджер с помощью множественного наследования. `super()` в переопределённых методах передаёт выполнение далее по MRO; файл открывается и закрывается методами `FileManager`, а дополнительные методы проверяют доступ и выводят сообщения. Порядок поиска методов доступен через `FileManagerWithLogging.__mro__`.
