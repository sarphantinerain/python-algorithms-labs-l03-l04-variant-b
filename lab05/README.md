# Лабораторная работа 05 — две части, вариант B

В эту папку добавлены только файлы пятой лабораторной. Для запуска нужен Python 3.10+; внешние библиотеки не требуются. Из корня проекта запустите обе части с выводом результатов:

```bash
python lab05/part1_cars.py
python lab05/part2_orm_variant_b.py
```

Проверки:

```bash
python -m unittest lab05.test_lab05 -v
```

## Часть 1: автомобили и CSV

В `part1_cars.py` класс `CarBase` хранит общие поля: `car_type`, `brand`, `photo_file_name`, `carrying`. Конструктор проверяет обязательные значения, допустимое расширение изображения и конечную неотрицательную грузоподъёмность. Метод `get_photo_file_ext()` возвращает расширение через `os.path.splitext()`.

Наследники добавляют только свои поля. `Car` хранит число пассажирских мест, `Truck` — три габарита и метод расчёта объёма, `SpecMachine` — дополнительное описание. `__slots__` фиксирует поля каждого типа, поэтому атрибуты других видов техники не появляются случайно. Габариты грузовика разбираются из строки вида `ДxШxВ`; если формат неверен, все три значения становятся нулями, а строка CSV сохраняется.

`get_car_list()` читает `cars.csv` стандартным модулем `csv` с разделителем `;`, пропускает заголовок и некорректные строки. При неизвестном типе техники, неверном числе мест, грузоподъёмности, фотографии или отсутствии обязательных полей объект не создаётся. В приложенном CSV четыре корректные записи; запись без расширения фотографии и пустая строка пропускаются. Время обработки — **O(n)** для `n` строк, память — **O(m)** для `m` созданных объектов.

## Часть 2: мини-ORM варианта B

В `part2_orm_variant_b.py` `Field` работает как дескриптор: `__set_name__()` фиксирует имя поля, `__get__()` читает значение экземпляра, `__set__()` проверяет тип. `IntegerField`, `StringField` и `FloatField` добавляют правила для целых чисел, ограниченной по длине строки и конечного вещественного числа; методы `to_db_value()` и `from_db_value()` задают преобразование при сохранении и чтении.

`ModelMeta` собирает поля из класса и его родителей, определяет имя таблицы и первичный ключ, а каждой модели выделяет своё хранилище записей в памяти. `Model.save()` автоматически назначает целый ID новой записи или обновляет существующую. `get()`, `filter()` и `delete()` читают и удаляют записи. `save()` и `delete()` возвращают пару `(SQL с плейсхолдерами ?, параметры)`: это только представление запроса, реальной базы данных здесь нет. Данные хранятся в словаре модели и исчезают после завершения процесса.

`QuerySet` сохраняет условия фильтрации, порядок сортировки и лимит без немедленного обхода записей. При итерации он применяет цепочку к текущему содержимому таблицы. `first()`, `count()` и `__len__()` используют тот же механизм. Префикс `-` в `order_by()` означает сортировку по убыванию.

`TransactionManager` при входе в `with` делает снимок таблиц и счётчиков ID. При нормальном выходе снимок отбрасывается, при исключении вызывается `rollback()` и таблицы восстанавливаются; исключение не скрывается. Откат касается сохранённых записей в памяти ORM, но не меняет уже существующие объекты Python вне хранилища. Классы `User` и `Article` реализованы по шаблону варианта B и используют этот общий механизм.
